# September 2026 frontend and product changes

This records the work requested to improve Chessplain's appearance, user flow, product framing, and supporting app reliability. Changes are local; no deployment, live payment, production migration, or customer-data operation was performed. Existing uncommitted homepage/style work was used as a starting point. This record describes the resulting changes, not an assertion that every line in the working-tree diff was newly authored in this task.

## 1. Shared visual design

Files: `apps/web/app/globals.css`, `app/layout.tsx`, `public/icon.svg`, and shared review components.

- Refined the existing tournament-editorial direction into warm paper surfaces, dark green-gray ink, muted green actions, and a related green/neutral chessboard.
- Retained Newsreader for editorial headings, with plain sans-serif interface text and monospace chess notation.
- Reworked shared navigation, footer, metadata, wordmark, and SVG favicon. Added a skip-to-content link.
- Consolidated page/form/button styling, visible focus states, input treatment, error states, text selection, and reduced-motion handling.
- Made homepage and pricing layouts stack on small screens. Kept navigation usable without hiding the sample or pricing links.
- Corrected typography CSS layer precedence so responsive Tailwind text utilities can override reusable type defaults.
- The implementation is light-theme only. The old documentation's dark theme and universal accessibility guarantees are not shipped claims.

See [DESIGN.md](../apps/web/DESIGN.md) for exact tokens and component conventions. A source-derived Impeccable sidecar exists locally at `apps/web/.impeccable/design.json`; `.impeccable` is ignored by Git and is not a runtime dependency.

## 2. Homepage and game submission

Files: `apps/web/app/page.tsx`, `lib/api.ts`, `lib/demo-report.ts`.

- Moved game submission into the main hero, replacing the large decorative-board lead with a working sample preview.
- Replaced rotating A/B/E acquisition copy with the stable promise, “A little clarity. A better next game.” The page identifies this version as `editorial_v1`.
- Preserved Chess.com username and PGN submission. Added an explicit White/Black choice for pasted PGN, transmitted as `player_color`.
- Added clearer source instructions, input limits, loading/disabled states, blank-input recovery, and a route to pricing/sign-in when allowance is exhausted.
- Removed automatic focus that could jump the page past the introduction. Added a synchronous submission guard against repeated clicks.
- Sends an available account token with submission so a paid user's entitlement can be recognized.
- Removed browser-storage dependence from the successful navigation path. Analytics must not stop an accepted report from opening.
- Added explanations of game selection, accountless free use, generated explanations, and link-accessible reports.

## 3. Sample and report reading flow

Files: `apps/web/lib/demo-report.ts`, `app/report/[id]/page.tsx`, `app/r/[shareId]/page.tsx`, `components/SharedReportInteractiveView.tsx`, `MomentCard.tsx`, `ChessboardView.tsx`.

- Replaced the old inconsistent sample with a clearly labeled illustrative game: `1. e4 e5 2. Bc4 Nc6 3. Qh5 Nf6 4. Qxf7# 1-0`.
- Sample positions are produced by legal chess.js replay. Its Black-side explanation matches the mating reply; there are no invented Elo ratings or customer claims.
- Consolidated the core private-route/shared-route reading UI into one interactive review component. “Private-route” here means the original report URL, not access control: both report links are publicly readable by link holders.
- Shows a summary, selectable key moments, one active lesson, and a next-game habit instead of a long stack of competing cards and an evaluation sparkline.
- Added Back/Show move/Continue controls, an explicit board flip, a replayable calculated continuation, and comparison with the available alternative.
- Replays only legal positions and stops at the last successful move. Arrow keys operate inside the continuation-control region rather than intercepting unrelated page input.
- Changed inferred-intention framing to “The idea may have been”; displays the concept definition and distinguishes the proposed intention from board consequences.
- Fixed duplicated move-number display when the engine's authoritative move already contains notation such as `23...Nf6`.
- Added an empty-result state for completed reports with no moments.
- Demo sharing points to a real sample route; the historical `demo-sample` shared URL is also handled locally.

## 4. Report loading, recovery, saving, and sharing

File: `apps/web/app/report/[id]/page.tsx`.

- Stops stream/watchdog/polling work on terminal states so completed reports do not later turn into a false stalled screen.
- Uses periodic snapshots alongside SSE to recover missed final messages or blocked stream connections.
- Merges streamed moments by ply, keeps chronological ordering, and accepts final moments and summary together.
- Distinguishes an unreadable report, failed analysis, queued analysis, active analysis, and slow/disconnected updates. Recovery actions match those states.
- Keeps readable progress visible during a slow connection and offers reconnection.
- Handles clipboard failure with a selectable share URL instead of silently failing.
- Handles Supabase's returned email error before showing success; disables repeated sends and explains the same-browser email-link requirement.
- Tracks completed-report dwell rather than counting waiting time as report engagement.

These are source and locally checked behaviors. Live stream interruption, SMTP delivery, and production queue recovery still need staging tests.

## 5. Authentication, pricing, and payments

Files: `apps/web/app/pricing/page.tsx`, `app/auth/callback/page.tsx`, `lib/api.ts`, `apps/engine/src/http/server.ts`.

- Retained the pre-existing $9.99/month and $99.99/year offers. No new price research or cost-based price calculation was performed.
- Clarified the actual paid benefit: the same reports without the free weekly allowance, for personal use, subject to rate limits and fair use.
- Removed unsupported claims about instant results, priority processing, and permanent report history from the pricing page.
- Requires sign-in before checkout and derives payment identity from a verified token on the server rather than accepting a client-supplied user ID/email.
- Adds an authenticated Stripe customer-portal endpoint and a Manage subscription action.
- Adds an existing-subscription check and a checkout idempotency key containing the user, selected price, and time bucket. This is duplicate-request protection, not proof that every concurrent checkout case is solved.
- Uses the configured web origin for return URLs. The frontend checks Stripe redirect destinations.
- Handles checkout cancellation and return notices without treating a return URL as proof that the subscription activated.
- Updates subscription state from Stripe webhook data and propagates database errors so failed updates can be retried. Updated-subscription events consult current Stripe state.
- Missing billing configuration returns an unavailable response instead of crashing the analysis service on Stripe construction.
- Fixes auth callback recovery, repeated code exchange in development, safe return destinations, and return-to-report behavior. Report claiming is optional for reading the link.

The accountless free first experience remains. There is no implemented report-history library or private-report authorization. See [PRODUCT.md](../apps/web/PRODUCT.md#pricing-and-entitlement) for the current entitlement contract and [the assessment](PRODUCT_REVIEW_2026-09-06.md#monetization) for its provisional rationale.

## 6. API and data presentation

Files: `apps/web/lib/api.ts`, `apps/engine/src/http/server.ts`.

- Added a typed API error carrying HTTP status, bounded client requests, and readable network/error handling.
- Normalizes nested source-game information into player names, player side, result, and move count for rendering.
- Added PGN side to the submission contract and authorization headers for billing and report submission.
- Validates submission shape, username/PGN limits, side selection, conflicting sources, and maximum half-move count.
- Invalid supplied authentication is rejected rather than silently downgrading the request to anonymous.
- A failed allowance lookup returns a recoverable error rather than bypassing quota enforcement.
- SSE deduplicates by ply instead of array length, avoids overlapping database polls, and cleans up on response closure.

## 7. Engine and queue reliability

Files: `apps/engine/src/analysis/{pipeline,pgn,verify,explain}.ts`, `queue/worker.ts`.

- Removed premature completion publication from the analysis pipeline. The worker persists the final moments and summary before setting completed status.
- Serializes incremental moment snapshots so later publications cannot be overwritten by older concurrent snapshots.
- Checks database errors on progress/moment/final writes and clears queue locks on completion, retry, and restart recovery.
- Preserves the requested Chess.com player when retrying an import whose PGN has already been saved. Persists player names and side for the frontend.
- Honors PGN side metadata and custom starting FENs, including actual move numbers.
- Removes the fallback that forcibly labeled rejected candidates verified.
- Replaces unsupported fallback narratives about initiative loss or the opponent winning with explicit explanation-unavailable text and inspectable continuations.
- Does not invent a loss result or time control when game metadata is absent.
- Uses the authoritative candidate move in generated reports rather than trusting the LLM to reproduce it unchanged.

This remains one serial game worker with parallel engine position evaluation. Multi-replica leasing, comprehensive UCI fault recovery, and all production error paths were not implemented in this task.

## 8. Deployment configuration

Files: `apps/engine/src/config.ts`, `uci/engine-pool.ts`, `uci/uci-client.ts`, `http/server.ts`, `.env.example`.

- Makes hash memory and threads configurable per engine via `ENGINE_HASH_MB` and `ENGINE_THREADS`; positive integer settings are validated.
- Uses a 512 MiB default hash per process, retains a default pool of four, and removes the pool's hard-coded CPU pinning assumption.
- Sets Stockfish Threads before Hash.
- Makes proxy trust explicit through `TRUST_PROXY`; the default no longer trusts arbitrary forwarded client addresses.
- Initializes the engine pool before listening, returns an unhealthy response when no engine is present, exits on fatal worker startup failure, and adds shutdown signal handling.
- Documents environment examples, a systemd service, reverse-proxy SSE handling, single-worker constraints, database/auth/Stripe prerequisites, and acceptance testing for the reported 24GB VPS.

RAM alone does not establish throughput. CPU allocation, actual report latency, process memory, and external-provider behavior still require measurement. Nothing was deployed or benchmarked on the VPS.
